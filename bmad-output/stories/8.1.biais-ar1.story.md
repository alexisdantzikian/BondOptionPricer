## Story

En tant que **membre du jury**,
je veux **voir que la vitesse de retour AR(1) du spread est compatible avec une vitesse nulle une fois son
biais de petit échantillon pris en compte**,
afin de **ne pas lire dans ses valeurs (0,19 ; 0,97 ; 5,03 selon la fenêtre) une contradiction avec
$a_y \approx 0$ retenu pour le pricing**.

## Dev Notes

<!-- LOCKED. Concrete guidance compiled from the planning docs WITH SOURCE CITATIONS. -->

**Contexte et objectif**
- Le §9.2 imprime, pour comparaison, la vitesse AR(1) du niveau du spread ; au tenor 20 ans elle vaut
  0,192 (2021-2026, n = 1 453), 0,966 (3 ans, n = 764), 5,028 (1 an, n = 257) et le texte dit qu'elle
  « varie d'un ordre de grandeur selon la fenêtre » [Source: main/oat_option_pricer.ipynb §9.2].
- Ce comportement en $1/n$ est le biais de petit échantillon de l'estimateur MCO d'un AR(1) très persistant
  (« persistence problem ») [Source: doc/econo modele affine.pdf, slides 46-55]. Approximation de Kendall :
  biais $\approx -(1+3\phi)/n$ sur $\hat\phi$ ; elle sous-estime le biais près de la racine unitaire
  (pour $\phi = 0{,}99$, $n = 160$ : −0,025 contre −0,034 exact) [Source: doc/econo modele affine.pdf, slide 53].
  Corrections proposées par le cours : inférence indirecte, bootstrap, Kendall, médiane non biaisée
  [Source: doc/econo modele affine.pdf, slide 53].
- Exigence : distribution sous vitesse nulle, rang de la valeur observée, vitesse corrigée par fenêtre ;
  conclusion de compatibilité avec $a_y \approx 0$ ; graine fixée [Source: prd.md#FR-020].
- Simulation exploratoire (hors notebook, 4 000 marches aléatoires, MCO avec constante) : sous $a = 0$,
  moyenne 0,94 / 1,80 / 5,46, intervalle 5-95 % [0,03 ; 2,43] / [0,10 ; 4,83] / [0,19 ; 14,2], rang de
  l'observé 13 % / 33 % / 56 % ; avec $a = 0{,}2$, l'intervalle pour n = 1 453 est [0,18 ; 2,81]
  [Source: addendum.md#fr-020--biais-de-la-vitesse-ar1--simulation-exploratoire-2026-10-01].
- Conséquence attendue : les trois valeurs observées sont **sous** la moyenne simulée à $a = 0$, donc
  `a_corrige` = 0 pour les trois fenêtres (y compris « 1 an » : 5,03 < 5,46, même si le rang est 56 %
  car la loi est asymétrique, médiane 4,37) [Inference]. Le markdown doit refléter ce que le notebook
  imprime réellement.

**Décisions d'architecture à appliquer**
- Structure du §9 : 9.1 inchangé, 9.2 « ce que l'historique identifie », 9.3 GMM (créée par la story 8.2),
  9.4 vitesse historique et biais [Source: architecture.md#ADR-010]. La story 8.2 insérera le §9.3 **entre**
  la cellule d'exécution du §9.2 et le markdown du §9.4 ; d'ici là le §9.4 suit directement le §9.2 —
  écart de numérotation transitoire accepté [Inference].
- Méthode : pour chaque fenêtre de `fenetres`, vitesse observée par `ar1_speed` (existant), distribution
  de l'estimateur sous $a = 0$ avec 2 000 trajectoires de même longueur, graine 2, simulées par
  `scipy.signal.lfilter` ; moyenne, quantiles 5 % et 95 %, rang de l'observé ; vitesse corrigée par
  inférence indirecte (moyenne simulée = observée), mêmes chocs pour tous les $a$, `brentq` sur $[0 ; 20]$,
  0 si l'observé est sous la moyenne à $a = 0$ [Source: architecture.md#ADR-010].
- Noms publics créés : `simulate_ar1_speeds(a, n, n_sim=2000, seed=2) -> ndarray[n_sim]`,

  Entité `AR1` : index fenêtre (`"2021-2026"`, `"3 ans"`, `"1 an"`), colonnes `n, a_obs, moy_a0, q05_a0,
  q95_a0, rang_obs, a_corrige` [Source: architecture.md#entity-ar1-dataframe-94].
- `AR1` sera lu par la story 8.2 pour le scénario $a_y$ du §11 (`AR1.loc["2021-2026", "a_corrige"]`)
  [Source: architecture.md#ADR-010].
- Graine 2 réservée à cette simulation ; `np.random.default_rng(2)` créé dans la fonction, pas de graine
  globale [Source: architecture.md#ADR-004].
- Noms publics lus : `est`, `fenetres`, `T_SJ`, `ar1_speed`, `np`, `pd` ; ne lire aucun nom transitoire
  d'une autre cellule (`rows`, `k`, `nom`, `t`, `start`…) [Source: architecture.md#ADR-002]. Les noms

**Détails d'implémentation**
- Régression : `ar1_speed` fait une MCO de $s_{t+1}$ sur $(1, s_t)$ sur la série de longueur `n`
  (n − 1 couples) et renvoie $-\log\hat\phi \times 252$ (NaN si $\hat\phi \ge 1$)
  [Source: main/oat_option_pricer.ipynb §9.2]. La simulation doit utiliser exactement le même estimateur et
  la même longueur `n` (= `est[fenêtre].loc[T_SJ, "n"]`).
- Pente MCO avec constante, vectorisée : pour `x = s[:, :-1]`, `y = s[:, 1:]`,
  $\hat\phi = \sum (x-\bar x)(y-\bar y) / \sum (x-\bar x)^2$ par ligne. Pour une trajectoire simulée,
  $\hat\phi \ge 1$ donne une vitesse 0 (troncature à zéro, à dire dans le markdown) — différent du NaN de
  `ar1_speed`, sans effet sur les valeurs observées qui sont toutes positives [Inference].
- Trajectoires : `lfilter([1.0], [1.0, -phi], eps, axis=1)` donne $s_t = \phi s_{t-1} + \varepsilon_t$ avec
  $s_{-1} = 0$ ; la variance des chocs est sans effet sur $\hat\phi$ (invariance d'échelle) [Inference].
- Nombres aléatoires communs : `simulate_ar1_speeds` recrée `default_rng(seed)` à chaque appel ; avec la
  même graine, les chocs sont identiques pour tous les $a$, ce qui rend la moyenne simulée lisse et
  croissante en $a$ et permet `brentq` [Inference].
- `ar1_corrige` : $g(a) = \text{moyenne}(\text{simulate\_ar1\_speeds}(a, n)) - a_{obs}$ ; si $g(0) \ge 0$ →
  0 ; sinon `brentq(g, 0, 20)` ; si $g(20) < 0$ → imprimer un avertissement et renvoyer `np.nan`
  [Inference]. À $a = 20$, $\phi = e^{-20/252} \approx 0{,}924$ et la moyenne dépasse largement les valeurs
  observées [Inference].
- Coût : 2 000 × 1 453 réels ≈ 23 Mo par simulation ; une dizaine d'évaluations au plus par fenêtre
  (souvent une seule, à $a = 0$, si la correction est nulle) ; quelques secondes au total
  [Source: architecture.md#6-api-specifications--interfaces] (section Performance).
- Rang : `rang_obs` = part des vitesses simulées sous $a = 0$ inférieures ou égales à `a_obs`.
- Affichage (ADR-005) : titre `vitesse de retour AR(1) du spread au tenor 20 ans, par an — distribution
  sous a = 0 (2 000 trajectoires, graine 2)`, tableau arrondi à 3 décimales (`rang_obs` en %), puis une
  ligne par fenêtre `vitesse corrigée (inférence indirecte) : valeur   (0 si l'observé est sous la moyenne
  à a = 0)` [Source: architecture.md#ADR-005].

**Texte attendu (en substance)**
- Markdown §9.4 : (1) la régression AR(1) du niveau, $s_{t+\delta} = c + \phi s_t + \varepsilon$, donne une
  vitesse **historique** $a = -\log\phi/\delta$ ; (2) sur une série très persistante, $\hat\phi$ est biaisé
  vers le bas en petit échantillon (Kendall), donc la vitesse vers le haut, d'environ $252(1+3\phi)/n$ par
  an : ≈ 0,7, 1,3 et 3,9 pour les trois fenêtres [Inference: calcul avec $\phi \approx 1$] — c'est l'ordre
  de grandeur des valeurs observées ; (3) Kendall sous-estime ce biais près de la racine unitaire, d'où la
  simulation : on tire la loi de l'estimateur sous $a = 0$ et on corrige par inférence indirecte (cours de
  Monfort, Pegoraro et Renne, `doc/econo modele affine.pdf`, slides 46-55) ; (4) conclusion selon
  `AR1` ; (5) la vitesse qui entre dans le pricing est la vitesse risque-neutre identifiée par la structure
  par terme des volatilités (§9.2 — la story 8.2 remplacera ce renvoi par §9.3).
- Phrase de renvoi dans le §9.2 : « La vitesse de retour historique, tirée d'une régression AR(1) du niveau
  du spread, est discutée au §9.4 : sa variation selon la fenêtre est un biais de petit échantillon. »
  [Inference]
- Interdits : « knock-out », paramètre de perte L, chiffres du papier de Russo [Source: architecture.md#ADR-006].
